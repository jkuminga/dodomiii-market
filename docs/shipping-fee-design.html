Dodomi · Shipping Policy Design

배송비 설정과 도서산간 체크 설계안

관리자가 기본 배송비·제주 추가금·도서산간 추가금을 설정하고, 주문 시 제주도는 카카오 우편번호의 sido, 도서산간은 고객 체크박스로 판별하는 1차 구현안입니다.

결정된 정책

V1 확정 방향
주문 범위
일반 주문만 적용합니다. 장바구니 주문은 장바구니 전체 상품, 바로구매는 바로구매 상품을 계산합니다.
상품 금액
백엔드가 계산한 할인·옵션 포함 최종 상품 금액을 무료배송 기준으로 사용합니다.
지역 판별
sido === 제주특별자치도이면 제주도, 그 외에는 주문자가 선택한 도서산간 체크박스를 사용합니다.
추가금 우선순위
제주도와 도서산간 추가금은 중복하지 않습니다. 제주도이면 제주 추가금, 제주도가 아니면서 체크했으면 도서산간 추가금을 적용합니다.
기록
최종 배송비는 주문에 저장합니다. 이후 관리자가 설정을 바꿔도 이미 생성된 주문 금액은 변하지 않습니다.

구현 전 확인사항

주소 데이터와 UI 상태를 먼저 검증합니다.

1. 카카오 sido 값 확인

카카오 공식 문서상 일반 시·도 값은 축약될 수 있지만, 제주특별자치도는 축약 대상에서 제외됩니다. 공식 예시의 제주 주소도 제주특별자치도 제주시 ... 형태입니다.

카카오 우편번호 공식 가이드 확인

예상 판별값: sido === '제주특별자치도'

제주시·서귀포시는 sigungu 값이므로 제주도 판별에 사용하지 않습니다.

2. 실제 응답 테스트

구현 전에 제주도 도로명 주소와 지번 주소를 각각 선택하여 다음 값을 확인합니다.

확인값목적
sido제주 자동 판별 기준
sigungu제주시·서귀포시가 별도 값으로 나오는지 확인
roadAddress / jibunAddress저장·표시 주소가 정상인지 확인

주소 재검색으로 제주도↔일반 지역을 바꿀 때 체크박스 상태도 함께 초기화해야 합니다.

구현 단계

검증 → 설정 → UI → 주문 계산 순서

01 · VERIFY카카오 응답 검증제주 도로명·지번 주소의 sido 확인
02 · DATAShippingSetting 생성단일 행 설정 테이블과 관리자 upsert API
03 · UI주소 상태 반영제주 판별 완료 시 체크박스 disabled
04 · ORDER서버 최종 계산결과를 orders.shipping_fee에 스냅샷

데이터 흐름

프론트는 예상 금액을 표시하고, 백엔드가 최종 금액을 결정합니다.

DB 설계

기존 StorefrontSetting과 같은 singleton 패턴

ShippingSetting 테이블

model ShippingSetting {
  key                    String   @id @default("default")
  baseShippingFee        Int      @default(3000)
  jejuAdditionalFee      Int      @default(3000)
  islandAdditionalFee    Int      @default(5000)
  freeShippingEnabled    Boolean  @default(true)
  freeShippingThreshold  Int      @default(10000)
  createdAt              DateTime @default(now())
  updatedAt              DateTime @updatedAt
}

금액은 원 단위 정수입니다. key는 설정 행의 식별자이며, 현재는 default 한 값만 사용합니다.

주문 스냅샷

필드역할
orders.shipping_fee주문 생성 당시 최종 배송비. 기존 필드 재사용
orders.shipping_region서버가 계산한 NORMAL / JEJU / ISLAND 구분
order_contacts.is_remote_area고객이 체크박스에서 입력한 도서산간 여부

ShippingRegion은 배송 지역 구분값입니다. 이후 외부 API로 교체해도 주문 구조를 유지할 수 있습니다.

왜 설정을 주문에 복사하지 않나요? 설정은 현재 정책이고 주문은 과거 거래 기록이기 때문입니다. 주문에는 계산 결과를 저장하고, 사용된 지역 구분만 보존하면 과거 주문 금액이 관리자 설정 변경의 영향을 받지 않습니다.

배송비 계산 규칙

숫자 배송비는 클라이언트가 보내지 않습니다.

eligible = freeShippingEnabled && totalProductPrice >= freeShippingThreshold;
baseFee = eligible ? 0 : baseShippingFee;

region = sido === '제주특별자치도'
  ? 'JEJU'
  : isRemoteArea
    ? 'ISLAND'
    : 'NORMAL';

additionalFee = region === 'JEJU'
  ? jejuAdditionalFee
  : region === 'ISLAND'
    ? islandAdditionalFee
    : 0;

shippingFee = baseFee + additionalFee;
finalTotalPrice = totalProductPrice + shippingFee;

일반 지역, 기준 미만기본 금액0원기본 금액
일반 지역, 기준 이상0원0원0원
제주도, 기준 이상0원제주 추가금제주 추가금
제주 외 도서산간, 기준 이상0원도서산간 추가금도서산간 추가금

UI 반영안

기존 페이지의 하드코딩 배송비를 설정값으로 교체

상품 상세 · 세부 가격
상품 금액10,000원
배송비3,000원

제주도 3,000원 / 도서산간 5,000원이 추가 부과됩니다.

주문 페이지 · 제주 주소 판별 완료 상태
상세 주소101호
제주도 추가금이 자동 적용되어 도서산간 체크박스는 선택할 수 없습니다.

제주도가 아닌 주소를 선택하면 체크박스가 다시 활성화됩니다. 체크하지 않았는데 도서산간이면 추가 금액이 요청될 수 있습니다.

API와 코드 영향 범위

현재 구조를 최대한 재사용합니다.

영역설계
관리자 APIGET /admin/shipping-settings, PUT /admin/shipping-settings. PUT은 key=default로 upsert합니다.
스토어 APIGET /store/shipping-settings. 금액 표시용 설정만 반환합니다.
주문 요청주소에 sido, isRemoteArea를 포함합니다. 프론트가 계산한 배송비는 보내지 않습니다.
주문 계산기존 resolveOrderItems의 서버 계산 상품 금액과 buildOrderPricingFromItems를 연결합니다.
기존 배송비 하드코딩백엔드 ORDER_SHIPPING_FEE와 프론트 ProductDetailPage·OrderPage·CartOrderPage의 3,000원 값을 DB 설정으로 대체합니다.
커스텀 주문관리자가 직접 입력한 CustomOrderLink.shippingFee는 별도 정책이므로 이번 무료배송 계산 대상에서 제외합니다.

리스크와 대응

이번 정책의 한계를 명시적으로 남깁니다.

리스크영향대응
도서산간 체크 누락주문 생성 시 추가금이 빠질 수 있음현재 운영 정책으로 수용하며, 운영자가 확인 후 후속 연락과 추가금 거래로 처리
카카오 주소값 변조클라이언트가 sido를 임의로 보낼 수 있음금액은 절대 클라이언트 값을 신뢰하지 않고 서버에서 계산. 추후 서버 측 주소 API 검증으로 교체 가능
관리자 설정 변경페이지 예상 금액과 제출 시 금액이 달라질 수 있음최종 주문 응답의 shippingFee와 finalTotalPrice를 주문 완료 화면 기준으로 사용
제주·도서산간 중복 체크추가금이 이중 부과될 수 있음제주 판별 완료 시 체크박스를 disabled하고, 서버에서도 제주 우선 판정 후 도서산간 추가금은 배제

이번 구현에서 하지 않는 것

Scope guard
  • 카카오 API나 외부 배송사 API로 도서산간을 자동 판별하지 않습니다.
  • 장바구니 상품 선택 체크박스를 추가하지 않습니다. 현재처럼 장바구니 전체를 주문합니다.
  • 주문 후 자동 추가결제·환불·부분 취소 흐름은 만들지 않습니다. 안내 문구만 제공합니다.
  • 배송사별 요금표나 배송사 선택 기능은 만들지 않습니다.
  • 관리자 설정 변경이 과거 주문 금액을 재계산하도록 만들지 않습니다.

추천 구현 순서: ShippingSetting 마이그레이션 → 관리자 설정 카드/API → 스토어 설정 조회 → 서버 주문 계산 → 주문 페이지 체크박스 → 상품 상세 안내 → 단위·통합 테스트 순서입니다.
